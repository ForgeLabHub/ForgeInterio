# Стиль кода и линт

## Что проверяется

| Инструмент | Версия | Конфигурация | Где запускается |
| --- | --- | --- | --- |
| ruff | `ruff==0.8.4` (`requirements-dev.txt`) | `ruff.toml` | `make lint`, CI job «Tests and lint» |
| pytest | `python -m pytest -q` | `tests/conftest.py` | `make test`, CI |

Конфигурация лежит в репозитории, а не в редакторе: `ruff.toml` задаёт
`line-length`, `target-version = "py311"` и набор правил `E4,E7,E9,F`
(ошибки и потенциальные баги). Версия ruff закреплена, поэтому `make lint`
локально и в CI дают одинаковый результат.

## Почему набор правил узкий

Код разделён на модули `app/`, но историческое наследие осталось: широкие
`except Exception` в фоновых задачах, открытие файлов без контекстного менеджера. Включение `BLE`, `SIM`, `PLW`
даёт 14 замечаний, которые нельзя исправить одним движением без риска для
поведения приложения. Поэтому:

1. Блокирующими остаются правила, которые ловят настоящие ошибки.
2. `docs/audit/portability-audit-2026-10-29.md` фиксирует долг по стилю.

## Как ужесточать

1. Взять одно правило (например `BLE001`).
2. Добавить его в `select`, поставить `# noqa: BLE001` с комментарием в
   местах, где широкий перехват осознанный (фоновые задачи keep-alive,
   отправка письма).
3. Убрать `noqa` там, где можно сузить тип исключения.
4. Только после этого расширять `select` дальше.

## Локальные команды

```bash
make lint    # ruff по app/, server.py, tests и tools
make test    # pytest, без сети и без секретов
make check   # lint + test + docs-check
```
