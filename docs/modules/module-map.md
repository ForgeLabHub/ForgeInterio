# Карта модулей: что заимствовать в другой проект

Пакет `app/` собран так, чтобы части можно было уносить по отдельности. Таблица
ниже — «что брать, если нужно X»: минимальный набор файлов, зависимости и что
придётся заменить.

| Нужно | Взять файлы | Внешние зависимости | Заменить |
| --- | --- | --- | --- |
| Регистрация, вход, сессии на cookie | `app/security.py`, `app/routers/auth.py`, `app/models.py` | `fastapi`, `pydantic` | таблицы `users`/`sessions` из `app/db.py` или свой репозиторий |
| Только пароли и токены | `app/security.py` (`hash_password`, `validate_password`, `create_session`) | — | `db.cursor` на свой доступ к базе; для нового проекта взять `argon2`/`bcrypt` вместо SHA-256 |
| SQLite-слой без ORM | `app/db.py` целиком | — | `SCHEMA` и `ADDED_COLUMNS` под свои таблицы |
| Отправка писем с вложениями | `app/mailer.py` | — | ничего: конфигурация приходит через `SmtpSettings` |
| Админ-доступ по коду из окружения | `app/security.py` (`check_admin_code`, `require_admin`) | `fastapi` | список разрешённых ролей |
| Заявка/форма с валидацией | `app/routers/quiz.py` (`validate`, `normalize_phone`) | `fastapi` | предметные поля и тексты |
| Конфигурация из окружения | `app/config.py` | — | набор полей `Settings` |
| HTML-страницы + API в одном процессе | `app/routers/pages.py`, `server.py` | `fastapi`, `uvicorn` | пути к шаблонам и статике |
| Опциональный keep-alive | `app/keepalive.py` | `requests` | URL и интервал |

## Правила переноса

1. **Один модуль — один смысл.** Если для переноса нужно «ещё три файла», это уже не
   модуль, а система: берите её целиком.
2. **Зависимости видны сверху.** Каждый модуль импортирует только то, что перечислено в
   таблице; скрытых обращений к глобальному состоянию нет — конфигурация читается
   функцией `settings()`, а не на импорте.
3. Оставлено намеренно **плоским**: никаких базовых классов и регистрации плагинов — их
   нельзя перенести без переноса всей иерархии.
4. **Тесты — часть модуля.** Забирая модуль, забирайте его тесты:
   `security` → `tests/test_auth.py`, `tests/test_security.py`; `quiz` → `tests/test_quiz.py`.
5. **Обратная совместимость.** `server.py` сохраняет `app` и `init_db`: старые импорты
   `from server import app` работают, внешние скрипты не ломаются.

## Чего здесь нет

- Нет `Repository`-абстракции и ORM: у проекта одна СУБД и один потребитель. Для проектов
  на PostgreSQL смотрите `docs/modules/` в ForgeRTKCRM (SQLAlchemy + Alembic).
- Нет системы плагинов и DI-контейнера: FastAPI `Depends` покрывает потребности
  (`security.require_admin`).
