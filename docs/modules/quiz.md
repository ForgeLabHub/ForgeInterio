# Модуль: квиз и заявки

## 1. Назначение и границы
Приём заявки квиза, валидация контактов и параметров, сохранение, просмотр и модерация
администратором. Не делает: не отправляет письма напрямую без конфигурации SMTP
(уведомление — опция).

## 2. Сценарии использования
- Заполнение квиза, согласие на обработку данных обязательно.
- Сохранение состояния квиза между шагами (`/api/session/save`).
- Просмотр своих заявок; админ видит все и меняет статус.
- Отказ: неверный email/телефон → 400; без согласия → 400.

## 3. Контракт
`POST /api/quiz/submit`, `GET /api/quiz/submissions`, `GET/PUT /api/admin/submissions`.
Схема запроса — `QuizSubmissionRequest`.

## 4. Данные
Пишет в `quiz_submissions` (контакты, параметры помещения, статус `new` по умолчанию).

## 5. Права
Отправка — доступна зарегистрированному пользователю; список всех заявок и изменение
статуса — только администратору (проверка роли на сервере, а не только в UI).

## 6. Зависимости
Исходящие: SQLite, `send_email` (опционально). Входящие: `static/quiz.js`.

## 7. Конфигурация
`SMTP_*` (включают письма), `DB_PATH`.

## 8. Сборка и отладка
```bash
python -m pytest tests/test_quiz.py -q
```

## 9. Тесты
`tests/test_quiz.py`: валидная заявка, обязательное согласие, проверка email, проверка
телефона, недоступность админ-списка без прав.

## 10. Наблюдаемость
Поток заявок виден в таблице и в админ-панели; ошибки — в stdout.
Ошибки: 400 (валидация), 401/403 (доступ).

## 11. Ограничения и готовность
- Нет уведомлений в мессенджер: только письмо и админ-панель.
- Нет выгрузки заявок в файл.
- Готовность: валидация покрыта тестами; админские данные недоступны без роли.
