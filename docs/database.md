# Хранение данных

SQLite, путь из `DB_PATH` (по умолчанию `data.db`). Схема создаётся при старте
идемпотентно: `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ... ADD COLUMN` в `try/except`.

## Таблицы

| Таблица | Содержимое | Владелец |
| --- | --- | --- |
| `users` | телефон, никнейм, хеш пароля, роль | аутентификация |
| `sessions` | токен сессии, пользователь, срок | аутентификация |
| `quiz_submissions` | заявка квиза (контакты, параметры комнаты, статус) | квиз/админ |

## Правила

1. **Пароли — только в виде хеша** (`hash_password`), минимум 8 символов и хотя бы одна
   буква (`validate_password`) — проверяется тестом.
2. **Сессия — HttpOnly cookie** `session_id`, `SameSite=lax`, срок 7 дней.
3. **Роль меняется только через админ-вход по коду из окружения**; без `ADMIN_CODE`
   маршрут отвечает 503 (fail closed).
4. **Тесты не касаются рабочей базы**: `DB_PATH` подменяется на временный файл.

## Резервное копирование

```bash
sqlite3 data.db ".backup 'backups/interio-$(date -u +%Y%m%dT%H%M%SZ).db'"
```

Восстановление: остановить приложение, заменить файл, запустить, проверить
`make smoke-test`. Для Render — скачать/загрузить файл через диск или пересоздать из
выгрузки заявок.

## Проверка

| Утверждение | Как проверяется |
| --- | --- |
| Схема создаётся на пустой базе | каждый тест поднимает приложение на пустом `DB_PATH` |
| Повторная инициализация безопасна | `init_db()` вызывается при каждом старте и в тестах |
| Пароль не хранится в открытом виде | `tests/test_auth.py` + ревью `hash_password` |
