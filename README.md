# Interio

Веб-приложение для дизайна интерьера с системой аутентификации пользователей и квизом для подбора стиля.

## ✨ Возможности

- 🔐 **Система аутентификации** - регистрация, вход, управление сессиями
- 🎨 **Интерактивный квиз** - подбор дизайна интерьера по предпочтениям
- 👨‍💼 **Админ панель** - управление заявками и пользователями
- 📱 **Адаптивный дизайн** - работает на всех устройствах
- 🔄 **Auto keep-alive** - предотвращение "сна" на Render.com

## 🛠️ Технологический стек

### Backend
- **FastAPI** - современный Python фреймворк
- **SQLite** - база данных
- **Pydantic** - валидация данных
- **Uvicorn** - ASGI сервер

### Frontend
- **Vanilla JavaScript** - без фреймворков
- **CSS3** - стилизация с анимациями
- **HTML5** - семантическая разметка

### Деплой
- **Render.com** - хостинг
- **Python 3.11** - среда выполнения
- **Auto keep-alive** - поддержка активности

## 🚀 Быстрый старт

### Локальный запуск

1. **Клонируйте репозиторий**
   ```bash
   git clone <repository-url>
   cd project-design
   ```

2. **Установите зависимости**
   ```bash
   pip install -r requirements.txt
   ```

3. **Запустите приложение**
   ```bash
   # Windows
   start.bat
   
   # Linux/Mac
   python server.py            # порт из PORT, по умолчанию 8000
   ```

4. **Откройте в браузере**
   ```
   http://localhost:8000
   ```

### Деплой на Render.com

1. **Подключите репозиторий к Render.com**
2. **Создайте Web Service**
3. **Используйте настройки из `render.yaml`**
4. **Установите переменные окружения:**
   - `APP_URL=https://your-app.onrender.com`

## 📋 API Эндпоинты

### Аутентификация
- `POST /api/auth/check-phone` - проверка телефона
- `POST /api/auth/login` - вход
- `POST /api/auth/register` - регистрация
- `POST /api/auth/logout` - выход
- `GET /api/auth/current-user` - текущий пользователь

### Квиз
- `POST /api/quiz/submit` - отправка заявки
- `GET /api/quiz/submissions` - список заявок

### Админ панель
- `POST /api/auth/admin-login` - вход в админку
- `GET /api/admin/submissions` - заявки для админа
- `PUT /api/admin/submissions/{id}` - обновление статуса

### Сессии
- `POST /api/session/data` - данные сессии
- `POST /api/session/save` - сохранение сессии

## 🎯 Функционал

### Для пользователей
- **Регистрация** по номеру телефона
- **Вход** в личный кабинет
- **Прохождение квиза** для подбора дизайна
- **Отправка заявки** на консультацию

### Для администраторов
- **Доступ** по админ коду (`ADMIN123`)
- **Просмотр** всех заявок
- **Управление** статусами заявок
- **Фильтрация** и сортировка

## Управление проектом: `forge.sh` и `forge.bat`

Один скрипт на Unix-подобные системы (`forge.sh`) и один на Windows
(`forge.bat`). Интерфейс одинаковый: те же команды, та же логика, одна
реализация на каждой платформе — без bash-скриптов внутри Windows.

```bash
./forge.sh              # интерактивное меню
./forge.sh doctor       # проверить окружение, ничего не меняя
./forge.sh install      # поставить зависимости
./forge.sh start        # запустить в фоне, дождаться готовности, открыть браузер
./forge.sh status       # что запущено и отвечает ли порт
./forge.sh logs api -f  # логи в реальном времени
./forge.sh test         # тесты
./forge.sh stop         # остановить
```

```bat
forge.bat
forge.bat start
forge.bat status
```

### Что умеет

| Команда | Действие |
| --- | --- |
| `status` | состояние по портам и HTTP, а не «на глаз» |
| `start [--fg]` | фон (PID-файлы в `.run/`) или передний план |
| `stop` | останавливает дерево процессов целиком, порт освобождается |
| `restart`, `logs [имя] [-f]`, `open` | обычные операции |
| `doctor` | инструменты, версии, `.env`, `.env` в git, занятость порта |
| `install`, `test`, `lint`, `build`, `verify` | через `make`, если он есть |
| `admin` | как задать `ADMIN_CODE` (без него админка отвечает 503) |

| `db migrate\|backup\|restore` | база: миграции, копия, восстановление |
| `docker up\|down\|logs\|reset` | контейнеры (`down` данные не удаляет) |
| `clean [--hard]` | артефакты и логи; `--hard` ещё `.venv` и `node_modules` |

### Правила, заложенные в скрипт

- **Ничего не меняет без команды.** `doctor` и `status` только читают.
- **Данные не удаляются.** `stop` и `docker down` сохраняют базу; удаление —
  только `--hard` или явное подтверждение в `docker reset`.
- **Предполётная проверка.** Если нет `go`/python или занят порт — скрипт
  говорит об этом сразу, а не через две минуты таймаута.
- **Не висит после падения.** Если процесс умер, запуск прекращается и
  показывает последние строки лога.
- **Venv главнее системы.** Если есть `.venv`, им пользуются `make`, `pytest`
  и uvicorn — чтобы `install` и `test` не расходились.

Текущий способ запуска без скрипта: `python server.py` — адрес `http://localhost:8000/`.

### Запуск в этом проекте

```bash

```
